# 4.1.2. PublicLayout

## 1. Introdução

O componente **PublicLayout** é responsável por estruturar todas as páginas públicas da aplicação, fornecendo um layout padrão que inclui cabeçalho, rodapé, espaçamento superior para compensar o header fixo e um container centralizado e responsivo. Ele garante consistência visual, facilita manutenção e elimina duplicação de estrutura entre as páginas públicas.

O layout utiliza **React**, componentes funcionais e **styled-components** para estilização, seguindo a abordagem modular adotada no projeto AquiTemFCTE.

## 2. Propósito

O componente **PublicLayout** tem como objetivos principais:

- **Padronizar a estrutura das páginas públicas**
- **Garantir consistência visual e responsividade**
- **Centralizar o conteúdo dentro de um limite máximo de largura**
- **Fornecer Header fixo e Footer constante em todas as páginas públicas**
- **Evitar duplicação de estrutura entre rotas públicas**

## 3. Estrutura do Componente

O componente é composto por:

- `Header`: cabeçalho fixo exibido em todas as páginas
- `EspacamentoTopo`: div que compensa a altura do header fixo (106px)
- `Centralização`: container externo que centraliza o conteúdo
- `Layout`: container interno com largura máxima responsiva
- `Footer`: rodapé exibido em todas as páginas
- `children`: conteúdo específico de cada página pública

## 4. Código do Componente

### 4.1. index.jsx

    import { Centralização, Layout, EspacamentoTopo } from "./style";
    import Header from "../../Header";
    import Footer from "../../Footer";

    const PublicLayout = ({ children }) => {
      return (
        <>
          <Header />
          <EspacamentoTopo />
          <Centralização>
            <Layout>
              <main>{children}</main>
            </Layout>
          </Centralização>
          <Footer />
        </>
      );
    };

    export default PublicLayout;

### 4.2. style.js

    import styled from "styled-components";

    export const Centralização = styled.div`
      display: flex;
      justify-content: center;

      @media (max-width: 800px) {
        justify-content: left;
        padding-inline: 20px;
      }
    `;

    export const Layout = styled.div`
      display: flex;
      flex-direction: column;
      justify-content: center;
      width: 1900px;

      @media (max-width: 2000px) {
        width: 90%;
      }

      @media (max-width: 800px) {
        width: 100%;
      }
    `;

    export const EspacamentoTopo = styled.div`
      height: 106px;
    `;

## 5. Props

| Prop       | Tipo      | Obrigatório | Descrição                                                |
| ---------- | --------- | ----------- | -------------------------------------------------------- |
| `children` | ReactNode | Sim         | Conteúdo da página que será renderizado dentro do layout |

## 6. Funcionamento e Responsividade

- O **Header é fixo**, então o `EspacamentoTopo` evita sobreposição do conteúdo.
- O container `Centralização` centraliza o conteúdo em telas grandes e aplica padding lateral em telas menores.
- O `Layout` limita a largura máxima a **1900px**, reduzindo para **90%** em telas médias e **100%** em telas pequenas.
- O Footer permanece sempre ao final da página.

## 7. Exemplo de Uso

    import PublicLayout from "../../../components/(layout)/PublicLayout";

    <PublicLayout>
      <Routes>
        <Route path="/login" element={<LoginPage />} />
        <Route path="/signup" element={<SignUpPage />} />
      </Routes>
    </PublicLayout>

## 8. Onde é Utilizado

- Rotas públicas da aplicação\`apps/web/src/routes/PublicRoutes.jsx`
- Todas as páginas que não exigem autenticação. Como:
  - Login
  - Signup
  - Recuperação de senha

## 9. Análise de Hotspots e Frozen-spots

### 9.1. PublicLayout como Framework Pattern

O componente **PublicLayout** é um exemplo perfeito da aplicação dos conceitos de **Frozen-spots** (pontos invariantes) e **Hotspots** (pontos de variação) na reutilização de software, implementando um **Framework Pattern** para layouts de página.

#### 9.1.1. Frozen-spots Identificados

**1. Estrutura Arquitetural Fixa**

```jsx
const PublicLayout = ({ children }) => {
  return (
    <>
      <Header /> // Frozen-spot: sempre presente
      <EspacamentoTopo /> // Frozen-spot: sempre necessário
      <Centralização>
        {" "}
        // Frozen-spot: container externo fixo
        <Layout>
          {" "}
          // Frozen-spot: container interno fixo
          <main>{children}</main> // Hotspot: conteúdo variável
        </Layout>
      </Centralização>
      <Footer /> // Frozen-spot: sempre presente
    </>
  );
};
```

**Análise dos Frozen-spots:**

- **Header**: Sempre presente em todas as páginas públicas
- **EspacamentoTopo**: Compensação fixa para header fixo (106px)
- **Centralização**: Container externo com lógica de centralização
- **Layout**: Container interno com largura máxima responsiva
- **Footer**: Sempre presente no final de todas as páginas
- **Estrutura JSX**: Ordem e hierarquia dos elementos nunca muda

**2. Padrões de Estilização Fixos**

```jsx
// Frozen-spots: estruturas de styled-components sempre iguais
export const Centralização = styled.div`
  display: flex; // Frozen-spot: sempre flex
  justify-content: center; // Frozen-spot: sempre centralizado

  @media (max-width: 800px) {
    // Frozen-spot: breakpoint fixo
    justify-content: left; // Frozen-spot: comportamento mobile
    padding-inline: 20px; // Frozen-spot: padding lateral
  }
`;

export const Layout = styled.div`
  display: flex; // Frozen-spot: sempre flex
  flex-direction: column; // Frozen-spot: sempre coluna
  justify-content: center; // Frozen-spot: sempre centralizado

  // Hotspots: valores responsivos podem variar
  width: 1900px; // Hotspot: largura máxima

  @media (max-width: 2000px) {
    width: 90%; // Hotspot: porcentagem responsiva
  }

  @media (max-width: 800px) {
    width: 100%; // Hotspot: largura mobile
  }
`;
```

**3. Interface de Props Padronizada**

```jsx
// Frozen-spot: interface sempre a mesma
interface PublicLayoutProps {
  children: ReactNode;              // Frozen-spot: sempre ReactNode
}

// Frozen-spot: padrão de uso sempre igual
<PublicLayout>
  {/* Hotspot: conteúdo específico da página */}
</PublicLayout>
```

#### 9.1.2. Hotspots Identificados

**1. Conteúdo das Páginas (children)**

```jsx
// Hotspot principal: diferentes páginas usando mesmo layout
<PublicLayout>
  <LoginPage />           // Hotspot: página de login
</PublicLayout>

<PublicLayout>
  <SignUpPage />          // Hotspot: página de cadastro
</PublicLayout>

<PublicLayout>
  <ForgotPasswordPage />  // Hotspot: página de recuperação
</PublicLayout>

<PublicLayout>
  <AboutPage />           // Hotspot: página institucional
</PublicLayout>
```

**2. Valores de Configuração Responsiva**

```css
/* Hotspots: valores podem ser ajustados conforme necessidade */
.layout {
  width: 1900px; /* Hotspot: largura máxima configurável */
}

@media (max-width: 2000px) {
  width: 90%; /* Hotspot: porcentagem ajustável */
}

@media (max-width: 800px) {
  width: 100%; /* Hotspot: comportamento mobile */
  padding-inline: 20px; /* Hotspot: padding lateral */
}
```

### 9.2. Framework Pattern na Prática

#### 9.2.1. Framework Core (Frozen-spots)

- **Estrutura de layout padronizada**: Header + Content + Footer
- **Sistema de centralização**: Container responsivo com largura máxima
- **Compensação de header fixo**: Espaçamento automático
- **Padrões de responsividade**: Breakpoints e comportamentos definidos
- **Interface de componente**: Props padronizadas e previsíveis

#### 9.2.2. Application Points (Hotspots)

- **Conteúdo específico**: Cada página injeta seu próprio conteúdo
- **Configurações responsivas**: Valores ajustáveis conforme necessidade
- **Extensões futuras**: Props adicionais para customização controlada

### 9.3. Benefícios da Abordagem

#### 9.3.1. Reutilização Efetiva

```jsx
// Frozen-spot: mesma estrutura, diferentes conteúdos (hotspots)
const LoginRoutes = () => (
  <PublicLayout>
    <Routes>
      <Route path="/login" element={<LoginPage />} />
      <Route path="/signup" element={<SignUpPage />} />
      <Route path="/forgot" element={<ForgotPasswordPage />} />
    </Routes>
  </PublicLayout>
);

const PublicRoutes = () => (
  <PublicLayout>
    <Routes>
      <Route path="/about" element={<AboutPage />} />
      <Route path="/contact" element={<ContactPage />} />
      <Route path="/terms" element={<TermsPage />} />
    </Routes>
  </PublicLayout>
);
```

#### 9.3.2. Manutenibilidade Centralizada

```jsx
// Mudança no frozen-spot afeta todas as páginas automaticamente
// Exemplo: alteração na altura do header
export const EspacamentoTopo = styled.div`
  height: 120px; /* Mudança centralizada afeta todas as páginas */
`;

// Exemplo: alteração na largura máxima
export const Layout = styled.div`
  width: 1440px; /* Nova largura máxima para todas as páginas */
  /* ...resto mantido igual... */
`;
```

#### 9.3.3. Evolução Sem Breaking Changes

```jsx
// Versão atual (frozen-spots mantidos)
<PublicLayout>
  <LoginPage />
</PublicLayout>

// Versão futura (hotspots adicionados, compatibilidade mantida)
<PublicLayout
  breadcrumbs={<Breadcrumbs />}
  alert={<Alert type="info">Sistema em manutenção</Alert>}
>
  <LoginPage />
</PublicLayout>
```

### 9.4. Comparação com Abordagens Alternativas

| Aspecto           | PublicLayout (Framework)                  | Duplicação Manual                  | Layout Inline                   |
| ----------------- | ----------------------------------------- | ---------------------------------- | ------------------------------- |
| **Reutilização**  | Alta - frozen-spots garantem consistência | Baixa - código duplicado           | Nenhuma - cada página diferente |
| **Manutenção**    | Centralizada nos frozen-spots             | Espalhada por todas as páginas     | Caótica e descentralizada       |
| **Consistência**  | Garantida pela estrutura                  | Dependente de disciplina manual    | Não garantida                   |
| **Performance**   | Otimizada - componentes reutilizados      | Ineficiente - duplicação de código | Problemática - recarregamento   |
| **Testabilidade** | Layout isolado e testável                 | Difícil testar consistência        | Cada página precisa ser testada |

## 10. Visão Crítica

### Pontos Fortes

- Estrutura simples e clara
- Facilita padronização visual
- Completamente responsivo
- Reaproveitável em qualquer rota pública

### Pontos de Melhoria

- Poderia suportar tema dinâmico (dark/light)
- Poderia incluir opção de ocultar Header ou Footer
- TypeScript ou PropTypes aumentariam a segurança de tipos

## 11. Conclusão

O componente PublicLayout é essencial para manter a organização e a padronização das páginas públicas do AquiTemFCTE. Sua estrutura simples, aliada ao uso de styled-components, ajuda a garantir uma experiência visual consistente e responsiva. Ao concentrar a lógica de layout em um único lugar, o projeto evita código duplicado e facilita bastante a manutenção. Embora ainda existam possibilidades de evolução, a implementação atual já atende muito bem às necessidades da aplicação.
