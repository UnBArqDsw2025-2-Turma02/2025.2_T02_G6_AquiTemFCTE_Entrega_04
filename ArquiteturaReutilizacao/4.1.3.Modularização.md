# 4.1.3. Modularização com o Design System

## 1. Introdução

Este documento descreve a modularização do **Design System** implementado no projeto AquiTemFCTE através do sistema de **Design Tokens**. Os tokens são a camada mais fundamental de um design system, representando decisões de design atômicas que podem ser reutilizadas em toda a aplicação.

Design tokens são variáveis que armazenam valores de design como cores, tipografia, espaçamentos e outros atributos visuais. Eles funcionam como uma "fonte única de verdade" para o design da aplicação, garantindo consistência visual e facilitando manutenção (SALESFORCE, 2023).

No projeto AquiTemFCTE, os tokens estão organizados em `apps/web/src/tokens` e são implementados utilizando **CSS Custom Properties (variáveis CSS)**, permitindo que sejam facilmente consumidos por qualquer componente da aplicação sem necessidade de importações JavaScript adicionais.

A abordagem de design tokens traz benefícios significativos: facilita a manutenção ao centralizar valores de design, permite mudanças globais com alterações mínimas, garante consistência visual em toda a aplicação e facilita a implementação de temas (DESIGN TOKENS COMMUNITY GROUP, 2024).

## 2. Propósito

O sistema de Design Tokens do projeto tem como objetivos principais:

- **Consistência Visual**: Garantir que cores, tipografia e outros atributos visuais sejam uniformes em toda a aplicação
- **Manutenibilidade**: Centralizar valores de design em um único local, facilitando atualizações globais
- **Escalabilidade**: Permitir que novos componentes e páginas utilizem os mesmos padrões visuais sem duplicação
- **Tematização**: Facilitar a implementação de temas alternativos (ex: modo escuro) através da alteração de variáveis CSS
- **Documentação Viva**: Servir como referência visual e técnica para desenvolvedores e designers

## 3. Estrutura do Design System

O Design System está organizado em dois arquivos principais de tokens:

### 3.1. Arquitetura de Tokens

```
apps/web/src/tokens/
├── pallette.css      # Tokens de cores (paleta cromática)
└── typography.css    # Tokens de tipografia (fontes, tamanhos, pesos)
```

Cada arquivo define um conjunto específico de tokens utilizando CSS Custom Properties no seletor `:root`, tornando-os globalmente acessíveis em toda a aplicação.

## 4. Tokens de Cores (Palette)

### 4.1. Localização

**Arquivo**: `apps/web/src/tokens/pallette.css`

### 4.2. Descrição

O arquivo de paleta define as cores fundamentais do projeto, incluindo cores primárias, secundárias, terciárias e neutras. Cada cor principal possui uma variante escura para criar hierarquia visual e estados interativos.

### 4.3. Tokens Definidos

```css
:root { 
  --primary-color: #003A7A;
  --primary-color-dark: #002855;
  --secondary-color: #00822E;
  --secondary-color-dark: #005A1F;
  --tertiary-color: #ADAD98;
  --tertiary-color-dark: #7A7A66;
  --white: #EEEEEE;
  --black: #000000;
}
```

### 4.4. Paleta de Cores

| Token | Valor | Uso |
|-------|-------|-----|
| `--primary-color` | #003A7A | Elementos principais |
| `--primary-color-dark` | #002855 | Estados hover/active |
| `--secondary-color` | #00822E | Botões de ação |
| `--secondary-color-dark` | #005A1F | Estados hover/active |
| `--tertiary-color` | #ADAD98 | Elementos de suporte |
| `--tertiary-color-dark` | #7A7A66 | Bordas e divisores |
| `--white` | #EEEEEE | Backgrounds claros |
| `--black` | #000000 | Textos principais |

### 4.5. Exemplo de Uso

```css
/* Em styled-components */
const Button = styled.button`
  background-color: var(--secondary-color);
  color: var(--white);
  
  &:hover {
    background-color: var(--secondary-color-dark);
  }
`;

/* Em CSS puro */
.header {
  background-color: var(--primary-color);
  color: var(--white);
}
```

## 5. Tokens de Tipografia

### 5.1. Localização

**Arquivo**: `apps/web/src/tokens/typography.css`

### 5.2. Descrição

O arquivo de tipografia define todos os aspectos relacionados a texto: família de fontes, escala tipográfica modular, pesos de fonte e alturas de linha. Utiliza uma escala tipográfica baseada em proporção áurea (1.2) para criar hierarquia visual harmoniosa.

### 5.3. Família de Fontes

**Fonte Principal**: Alexandria (Google Fonts) - Fonte moderna e legível com suporte a pesos variáveis (100-900).

### 5.4. Escala Tipográfica

Escala modular com razão 1.2:

| Token | Valor | Uso |
|-------|-------|-----|
| `--fs-scale-up-04` | 2rem | H1 |
| `--fs-scale-up-03` | 1.728rem | H2 |
| `--fs-scale-up-02` | 1.44rem | H3 |
| `--fs-scale-up-01` | 1.2rem | H4 |
| `--fs-scale-base` | 1rem | Texto base |
| `--fs-scale-down-01` | 0.833rem | Textos pequenos |

### 5.5. Pesos de Fonte

Disponíveis: thin (100), light (300), regular (400), medium (500), semibold (600), bold (700), black (900).

### 5.6. Alturas de Linha

- `--font-lineheight-low: 115%` - Títulos
- `--font-lineheight-medium: 145%` - Textos curtos
- `--font-lineheight-high: 185%` - Parágrafos

### 5.7. Estilos Globais de Elementos HTML

O arquivo também define estilos padrão para elementos HTML, garantindo consistência automática:

```css
html {
  color: var(--black);
  font-family: var(--font-family);
  font-size: var(--fs-scale-base);
  font-weight: var(--fw-regular);
  line-height: var(--font-lineheight-low);
}

h1 {
  font-size: var(--fs-scale-up-04);
  font-weight: var(--fw-bold);
  line-height: var(--font-lineheight-low);
  margin: 0;
}

h2 {
  font-size: var(--fs-scale-up-03);
  font-weight: var(--fw-bold);
  line-height: var(--font-lineheight-low);
  margin: 0;
}

/* ... outros elementos ... */

label {
  font-size: var(--fs-scale-down-01);
  font-weight: var(--fw-semibold);
  line-height: var(--font-lineheight-low);
}

::placeholder {
  font-size: var(--fs-scale-down-01);
  font-weight: var(--fw-light);
}
```

### 5.8. Exemplo de Uso

```css
/* Uso direto dos tokens */
.custom-heading {
  font-size: var(--fs-scale-up-03);
  font-weight: var(--fw-bold);
  line-height: var(--font-lineheight-low);
}

/* Ou simplesmente usar elementos HTML nativos */
<h1>Título Principal</h1>  /* Já aplica os estilos automaticamente */
<h2>Subtítulo</h2>
<label>Campo de Formulário</label>
```

## 6. Integração com a Aplicação

### 6.1. Importação dos Tokens

Os tokens devem ser importados no ponto de entrada da aplicação para estarem disponíveis globalmente:

```javascript
// Em apps/web/src/main.jsx ou App.jsx
import './tokens/pallette.css';
import './tokens/typography.css';
```

### 6.2. Uso em Styled Components

Os tokens podem ser facilmente utilizados em styled-components:

```javascript
import styled from 'styled-components';

const Container = styled.div`
  background-color: var(--white);
  color: var(--black);
  font-family: var(--font-family);
  padding: 2rem;
`;

const Title = styled.h1`
  color: var(--primary-color);
  font-size: var(--fs-scale-up-04);
  font-weight: var(--fw-bold);
`;

const Button = styled.button`
  background-color: var(--secondary-color);
  color: var(--white);
  font-size: var(--fs-scale-base);
  font-weight: var(--fw-semibold);
  
  &:hover {
    background-color: var(--secondary-color-dark);
  }
`;
```

### 6.3. Uso em CSS Modules

```css
/* styles.module.css */
.card {
  background-color: var(--white);
  border: 1px solid var(--tertiary-color);
  border-radius: 8px;
}

.cardTitle {
  color: var(--primary-color);
  font-size: var(--fs-scale-up-02);
  font-weight: var(--fw-semibold);
}
```

## 7. Onde é Utilizado

Os tokens são utilizados em toda a aplicação:

- **Componentes de UI**: Button, Input, Header, Footer (`apps/web/src/components`)
- **Layouts**: PublicLayout, PrivateLayout (`apps/web/src/components/(layout)`)
- **Páginas**: Login, SignUp, Home, etc. (`apps/web/src/pages`)
- **Styled Components**: Todos os componentes estilizados com styled-components

## 8. Visão Crítica

A implementação do sistema de Design Tokens no projeto AquiTemFCTE representa uma abordagem madura e profissional para gestão de design em aplicações web. A escolha por CSS Custom Properties como base técnica demonstra compreensão das tecnologias nativas do navegador e preocupação com performance e compatibilidade.

A análise crítica deste sistema revela uma estrutura bem fundamentada que equilibra simplicidade de implementação com poder de expressão. A separação entre tokens de cores e tipografia cria uma organização lógica que facilita tanto a manutenção quanto a evolução do sistema. O uso de uma escala tipográfica modular baseada em proporção matemática (1.2) demonstra atenção a princípios de design, criando hierarquia visual harmoniosa e profissional.

No entanto, como todo sistema em evolução, existem oportunidades de expansão que podem elevar ainda mais a robustez e flexibilidade do design system. A adição de tokens para espaçamento, bordas e sombras, bem como a implementação estruturada de temas alternativos, são caminhos naturais para o amadurecimento do sistema.

### 8.1. Pontos Fortes

- **Implementação Nativa**: Uso de CSS Custom Properties garante compatibilidade e performance
- **Organização Clara**: Separação entre paleta e tipografia facilita manutenção
- **Escala Tipográfica Harmoniosa**: Proporção 1.2 cria hierarquia visual agradável
- **Variantes de Cores**: Cores escuras para estados interativos demonstram atenção a UX
- **Estilos Globais**: Definição de estilos para elementos HTML garante consistência automática

### 8.2. Pontos de Melhoria

- **Tokens de Espaçamento**: Adicionar tokens para margins, paddings e gaps aumentaria a consistência
- **Tokens de Bordas**: Incluir border-radius e border-width padronizados
- **Tokens de Sombras**: Definir elevações consistentes para cards e modais
- **Modo Escuro**: Implementar variáveis para tema escuro de forma estruturada
- **Documentação Visual**: Criar uma página de documentação visual (Storybook) mostrando todos os tokens
- **Validação**: Implementar testes para garantir que todos os tokens estão sendo utilizados corretamente
- **Nomenclatura**: Considerar migrar para nomenclatura mais granular (ex: `color-primary-700` ao invés de `primary-color`)

### 8.3. Impacto no Projeto

A implementação do sistema de Design Tokens tem impacto extremamente positivo:

- **Velocidade de Desenvolvimento**: Desenvolvedores não precisam decidir cores ou tamanhos de fonte
- **Consistência**: Garante que toda a aplicação siga o mesmo padrão visual
- **Manutenibilidade**: Mudanças de design podem ser feitas rapidamente
- **Escalabilidade**: Novos componentes automaticamente seguem o design system
- **Colaboração**: Facilita comunicação entre designers e desenvolvedores

## 9. Trabalho em Equipe

O desenvolvimento do sistema de Design Tokens foi um esforço colaborativo que envolveu diferentes frentes de trabalho. A equipe foi dividida em dois grupos principais: alguns membros focaram na **codificação dos tokens**, implementando os arquivos CSS com as variáveis de cores e tipografia, enquanto outros membros se dedicaram à **documentação técnica**, descrevendo a estrutura, propósito e uso dos tokens.

Essa divisão de responsabilidades permitiu que o trabalho avançasse de forma eficiente. O grupo de codificação trabalhou em conjunto para definir as decisões técnicas sobre a implementação com CSS Custom Properties. Simultaneamente, o grupo de documentação estruturou este documento para servir como referência técnica e conceitual.

A comunicação entre os grupos foi essencial para garantir que a documentação refletisse fielmente a implementação e que as decisões técnicas fossem bem fundamentadas e explicadas. Este processo colaborativo resultou em um sistema coeso e bem documentado, facilitando a compreensão e utilização dos tokens por toda a equipe de desenvolvimento.

## 10. Conclusão

O sistema de Design Tokens implementado no projeto AquiTemFCTE representa a base fundamental do design system da aplicação. Através da modularização de cores e tipografia em arquivos CSS dedicados, o projeto garante consistência visual, facilita manutenção e acelera o desenvolvimento.

A escolha por CSS Custom Properties demonstra maturidade técnica, priorizando soluções nativas e performáticas. A organização clara entre `pallette.css` e `typography.css` facilita a compreensão e manutenção do sistema.

Embora existam oportunidades de expansão (tokens de espaçamento, sombras, bordas), a implementação atual já fornece uma base sólida para o desenvolvimento de uma interface consistente e profissional. O sistema é extensível e pode evoluir conforme as necessidades do projeto crescem.

Este documento serve como referência técnica e conceitual para todos os desenvolvedores do projeto, garantindo que o Design System seja utilizado de forma eficaz e consistente.
