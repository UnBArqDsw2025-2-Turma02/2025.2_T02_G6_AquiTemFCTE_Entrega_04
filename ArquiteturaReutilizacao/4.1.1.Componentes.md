# 4.1.1. Componentes de UI

## 1. Introdução

Este documento descreve os componentes de interface de usuário (UI) reutilizáveis desenvolvidos para a aplicação web do projeto AquiTemFCTE. Os componentes foram criados seguindo princípios de design system, garantindo consistência visual e funcional em toda a aplicação.

Os componentes permitem que você divida a interface do usuário em partes independentes e reutilizáveis e pense em cada parte isoladamente (REACT, 2023). Esta abordagem modular é fundamental para o desenvolvimento de aplicações React modernas, pois facilita a organização e manutenção do código.

Com o crescimento das aplicações front-end, organizar o código de forma eficiente é crucial. Os componentes possibilitam essa organização ao isolar funcionalidades, facilitando a reutilização e modificação (ROCKETSEAT, 2024). Essa abordagem modular também aumenta a performance, pois cada componente é renderizado independentemente, o que é essencial para grandes aplicações (ROCKETSEAT, 2024).

Os componentes estão localizados em `apps/web/src/components` e são utilizados em diferentes páginas e contextos da aplicação, promovendo reutilização de código e manutenibilidade. Todos os componentes são implementados como componentes funcionais do React, utilizando hooks modernos e a biblioteca styled-components para estilização.

## 2. Propósito

O objetivo principal dos componentes de UI é:

- **Consistência Visual**: Garantir uma experiência visual uniforme em toda a aplicação
- **Reutilização**: Reduzir duplicação de código através de componentes genéricos e configuráveis
- **Manutenibilidade**: Facilitar atualizações e correções centralizadas
- **Produtividade**: Acelerar o desenvolvimento de novas funcionalidades
- **Acessibilidade**: Implementar padrões de acessibilidade de forma consistente

## 3. Reutilização

Os componentes foram projetados seguindo princípios de reutilização:

### 3.1. Componentes Atômicos

Cada componente é independente e pode ser utilizado isoladamente ou em combinação com outros:

- **Button**: Componente de botão com variantes de estilo
- **Input**: Campo de entrada de dados com suporte a múltiplos tipos
- **Header**: Cabeçalho da aplicação com navegação
- **Footer**: Rodapé da aplicação com links e informações
- **PopUp**: Modal/popup para exibição de conteúdo sobreposto
- **PublicLayout**: Layout público que estrutura páginas com Header e Footer

### 3.2. Customização via Props

Todos os componentes aceitam propriedades (props) que permitem customização sem necessidade de modificar o código fonte:

- Variantes de estilo (ex: `variant` no Button)
- Estados (ex: `disabled`, `required` no Input)
- Callbacks (ex: `onClick`, `onChange`)
- Conteúdo customizável (ex: `children`, `label`, `placeholder`)

### 3.3. Estilização com Styled Components

A estilização é feita utilizando `styled-components`, permitindo:

- Temas centralizados através de variáveis CSS
- Responsividade através de media queries
- Estados interativos (hover, focus, etc.)
- Manutenção facilitada de estilos

## 4. Utilização na Aplicação

### 4.1. Button

**Localização**: `apps/web/src/components/Button/`

**Descrição**: Componente de botão reutilizável com suporte a diferentes variantes visuais.

**Props**:

- `children` (ReactNode): Conteúdo do botão
- `variant` (string, opcional): Variante de estilo (`"default"` ou `"outlineBlue"`). Padrão: `"default"`
- `onClick` (function, opcional): Função executada ao clicar no botão

**Variantes**:

- `default`: Botão com fundo secundário e texto branco
- `outlineBlue`: Botão com borda azul e fundo transparente

**Exemplo de Uso**:

```jsx
import Button from "../../../components/Button";

<Button onClick={handleLogin}>Entrar</Button>
<Button variant="outlineBlue" onClick={handleSignUp}>
  Fazer Cadastro
</Button>
```

**Onde é utilizado**:

- Página de Login (`apps/web/src/pages/(public)/Login/index.jsx`)
- Página de SignUp (`apps/web/src/pages/(public)/SignUp/index.jsx`)
- Componente Header (`apps/web/src/components/Header/index.jsx`)

---

### 4.2. Input

**Localização**: `apps/web/src/components/Input/`

**Descrição**: Componente de campo de entrada versátil que suporta diferentes tipos de input, incluindo texto, senha e arquivo.

**Props**:

- `label` (string, opcional): Rótulo do campo
- `placeholder` (string, opcional): Texto de placeholder. Padrão: `"Digite aqui..."`
- `type` (string, opcional): Tipo do input (`"text"`, `"password"`, `"file"`, `"number"`, etc.). Padrão: `"text"`
- `onChange` (function, opcional): Função executada ao alterar o valor
- `icon` (boolean, opcional): Exibe ícone à esquerda do campo. Padrão: `false`
- `iconChildren` (ReactNode, opcional): Elemento do ícone a ser exibido
- `id` (string, opcional): ID do elemento. Gera automaticamente se não fornecido
- `required` (boolean, opcional): Indica se o campo é obrigatório. Padrão: `false`
- `accept` (string, opcional): Tipos de arquivo aceitos (para `type="file"`)
- `multiple` (boolean, opcional): Permite múltiplos arquivos (para `type="file"`)
- `disabled` (boolean, opcional): Desabilita o campo. Padrão: `false`
- `value` (string, opcional): Valor controlado do campo

**Funcionalidades Especiais**:

- **Tipo Password**: Exibe botão de mostrar/ocultar senha automaticamente
- **Tipo File**: Interface drag-and-drop com preview do nome do arquivo
- **Ícones**: Suporte a ícones personalizados à esquerda do campo

**Exemplo de Uso**:

```jsx
import Input from "../../../components/Input";
import { MdOutlineEmail } from "react-icons/md";

<Input
  label="Email Institucional"
  placeholder="Email Institucional"
  icon={true}
  iconChildren={<MdOutlineEmail />}
  value={email}
  onChange={(e) => setEmail(e.target.value)}
/>

<Input
  label="Senha"
  placeholder="Senha"
  type="password"
  required
  onChange={(e) => setPassword(e.target.value)}
/>

<Input
  label="Foto de Perfil"
  accept="image/*"
  type="file"
  onChange={handleFileChange}
/>
```

**Onde é utilizado**:

- Página de Login (`apps/web/src/pages/(public)/Login/index.jsx`)
- Página de SignUp (`apps/web/src/pages/(public)/SignUp/index.jsx`)

### 4.3. Header

**Localização**: `apps/web/src/components/Header/`

**Descrição**: Cabeçalho fixo da aplicação contendo logo, navegação, chamadas promocionais rotativas e ações do usuário.

**Funcionalidades**:

- **Chamadas Rotativas**: Exibe mensagens promocionais que alternam automaticamente a cada 10 segundos
- **Navegação**: Links para categorias (Eletrônicos, Livros, Roupas, Outros)
- **Ações**: Ícones de busca, chat, favoritos, perfil e botão de anúncio
- **Responsivo**: Menu hambúrguer em telas menores (< 880px)
- **Acessibilidade**: Ícones de acessibilidade e tema escuro

**Estrutura**:

- **Lettering**: Barra superior com chamadas promocionais e ícones de acessibilidade
- **NavLinks**: Barra principal com logo, links de navegação e ações

**Exemplo de Uso**:

```jsx
import Header from "../../Header";

<Header />;
```

**Onde é utilizado**:

- Componente PublicLayout (`apps/web/src/components/(layout)/PublicLayout/index.jsx`)

---

### 4.4. Footer

**Localização**: `apps/web/src/components/Footer/`

**Descrição**: Rodapé da aplicação contendo informações institucionais, links rápidos e redes sociais.

**Estrutura**:

- **Logo Estendido**: Logo da aplicação em versão estendida
- **Links Rápidos**: Navegação para páginas principais
- **Sobre Nós**: Informações sobre o projeto e instituição
- **Privacidade**: Links para políticas de privacidade
- **Contatos**: Ícones de redes sociais (Instagram, Facebook)
- **Copyright**: Informações de direitos autorais

**Responsividade**:

- Layout em coluna em telas menores (< 450px)
- Logo oculto em telas médias (890px - 450px)
- Links organizados em colunas em telas pequenas

**Exemplo de Uso**:

```jsx
import Footer from "../../Footer";

<Footer />;
```

**Onde é utilizado**:

- Componente PublicLayout (`apps/web/src/components/(layout)/PublicLayout/index.jsx`)

### 4.5. PopUp

**Localização**: `apps/web/src/components/PopUp/`

**Descrição**: Componente de modal/popup para exibição de conteúdo sobreposto, como confirmações, formulários ou informações importantes.

**Props**:

- `isOpen` (boolean): Controla a visibilidade do popup
- `onClose` (function): Função executada ao fechar o popup
- `disabled` (boolean, opcional): Desabilita o botão de fechar. Padrão: `false`
- `children` (ReactNode): Conteúdo a ser exibido dentro do popup

**Características**:

- Overlay escuro semi-transparente
- Centralização automática na tela
- Botão de fechar (×) no canto superior direito (pode ser desabilitado)
- Responsivo (largura máxima de 90% em telas pequenas)

**Exemplo de Uso**:

```jsx
import Popup from "../../../components/PopUp";

<Popup
  isOpen={isPopupOpen}
  onClose={() => setIsPopupOpen(false)}
>
  <h1>Título do Popup</h1>
  <p>Conteúdo do popup</p>
  <Button onClick={handleAction}>Ação</Button>
</Popup>

<Popup
  isOpen={isLoading}
  onClose={() => setIsLoading(false)}
  disabled
>
  <p>Aguarde...</p>
</Popup>
```

**Onde é utilizado**:

- Página de Login (`apps/web/src/pages/(public)/Login/index.jsx`) - Verificação de email e código
- Página de SignUp (`apps/web/src/pages/(public)/SignUp/index.jsx`) - Loading e sucesso de cadastro

---

### 4.6. PublicLayout

**Localização**: `apps/web/src/components/(layout)/PublicLayout/`

**Descrição**: Layout público que estrutura as páginas da aplicação, incluindo Header fixo, área de conteúdo centralizada e Footer.

**Props**:

- `children` (ReactNode): Conteúdo da página a ser renderizado

**Estrutura**:

- **Header**: Cabeçalho fixo no topo
- **EspacamentoTopo**: Espaçamento para compensar o header fixo (106px)
- **Centralização**: Container centralizado para o conteúdo
- **Layout**: Container principal com largura máxima responsiva
- **Footer**: Rodapé no final da página

**Características**:

- Header fixo que permanece visível durante o scroll
- Conteúdo centralizado com largura máxima de 1900px
- Responsivo: ajusta padding e largura em telas menores

**Exemplo de Uso**:

```jsx
import PublicLayout from "../components/(layout)/PublicLayout";

<PublicLayout>
  <Routes>
    <Route path={ROUTES.LOGIN} element={<LoginPage />} />
    <Route path={ROUTES.SIGNUP} element={<SignUpPage />} />
  </Routes>
</PublicLayout>;
```

**Onde é utilizado**:

- Rotas públicas (`apps/web/src/routes/PublicRoutes.jsx`)

## 6. Análise de Hotspots e Frozen-spots

### 6.1. Conceitos na Arquitetura de Componentes

Os componentes de UI do projeto AquiTemFCTE exemplificam claramente os conceitos de **Frozen-spots** (pontos estáveis/invariantes) e **Hotspots** (pontos de variação/extensão) na reutilização de software.

#### 6.1.1. Frozen-spots Identificados

**1. Estrutura Base dos Componentes React**

```jsx
// Frozen-spot: padrão estrutural que nunca muda
const Component = ({ prop1, prop2, children, ...props }) => {
  return <StyledComponent {...props}>{children}</StyledComponent>;
};

export default Component;
```

**2. Sistema de Props Padronizado**

- `children`: Sempre presente em componentes container
- `onClick`: Padrão para componentes interativos
- `disabled`: Padrão para controle de estado
- `className`: Para customização CSS externa

**3. Padrão Styled Components**

```jsx
// Frozen-spot: estrutura de estilização
import styled from "styled-components";

export const ComponentWrapper = styled.div`
  /* estilos base sempre presentes */
  display: flex;
  /* variações via props (hotspots) */
  background-color: ${(props) =>
    props.variant === "primary"
      ? "var(--primary-color)"
      : "var(--secondary-color)"};
`;
```

**4. Integração com Design System**

```jsx
// Frozen-spot: sempre usar tokens do design system
const StyledButton = styled.button`
  color: var(--white); // Frozen-spot: sempre usa token
  font-family: var(--font-family); // Frozen-spot: sempre usa token
`;
```

#### 6.1.2. Hotspots Identificados

**1. Componente Button - Variantes e Comportamentos**

```jsx
// Hotspots: diferentes variantes e ações
<Button variant="default" onClick={handleSubmit}>Enviar</Button>
<Button variant="outlineBlue" onClick={handleCancel}>Cancelar</Button>
<Button disabled onClick={handleDisabled}>Desabilitado</Button>
```

**Análise do Hotspot:**

- `variant`: Permite diferentes estilos visuais
- `onClick`: Permite diferentes comportamentos
- `disabled`: Permite diferentes estados
- `children`: Permite diferentes conteúdos

**2. Componente Input - Tipos e Funcionalidades**

```jsx
// Hotspots: diferentes tipos e comportamentos
<Input type="text" placeholder="Nome" />         // Texto simples
<Input type="password" placeholder="Senha" />    // Com toggle de visibilidade
<Input type="file" accept="image/*" />           // Drag and drop
<Input type="number" min="0" max="100" />        // Validação numérica
```

**Análise do Hotspot:**

- `type`: Determina comportamento fundamental
- `placeholder`: Customiza texto de ajuda
- Atributos específicos: `accept`, `min`, `max` etc.

**3. Componente PopUp - Conteúdo e Estados**

```jsx
// Hotspots: diferentes conteúdos e controles
<PopUp isOpen={true} onClose={handleClose}>
  <h2>Sucesso!</h2>                    // Hotspot: conteúdo variável
  <p>Operação realizada com sucesso</p>
</PopUp>

<PopUp isOpen={true} onClose={handleClose} disabled>
  <LoadingSpinner />                   // Hotspot: comportamento diferente
</PopUp>
```

**4. PublicLayout - Conteúdo das Páginas**

```jsx
// Frozen-spot: estrutura fixa do layout
const PublicLayout = ({ children }) => (
  <>
    <Header />           // Sempre presente
    <EspacamentoTopo />  // Sempre presente
    <Centralização>
      <Layout>
        <main>{children}</main>  // Hotspot: conteúdo variável
      </Layout>
    </Centralização>
    <Footer />           // Sempre presente
  </>
);

// Uso: diferentes páginas (hotspots) na mesma estrutura (frozen-spot)
<PublicLayout><LoginPage /></PublicLayout>
<PublicLayout><SignUpPage /></PublicLayout>
<PublicLayout><HomePage /></PublicLayout>
```

### 6.2. Framework Pattern na Prática

Os componentes implementam um **Framework de UI** onde:

#### 6.2.1. Framework Core (Frozen-spots)

- Estrutura base React
- Padrão de props
- Sistema styled-components
- Integração com design tokens
- Padrões de acessibilidade

#### 6.2.2. Application Points (Hotspots)

- Conteúdo específico (`children`)
- Variantes visuais (`variant`)
- Comportamentos (`onClick`, `onChange`)
- Estados (`disabled`, `required`)
- Configurações (`type`, `accept`, `placeholder`)

### 6.3. Benefícios da Abordagem

#### 6.3.1. Reutilização Eficiente

```jsx
// Mesmo frozen-spot, diferentes hotspots
<Button variant="default">Salvar</Button>      // Contexto: formulário
<Button variant="outlineBlue">Cancelar</Button> // Contexto: ação secundária
<Button disabled>Processando...</Button>        // Contexto: estado de loading
```

#### 6.3.2. Extensibilidade Controlada

```jsx
// Adicionando nova variante (hotspot) sem alterar estrutura (frozen-spot)
<Button variant="danger" onClick={handleDelete}>
  Excluir
</Button>;

// CSS correspondente
const StyledButton = styled.button`
  /* frozen-spot: estrutura base mantida */
  padding: 12px 24px;
  border-radius: 4px;

  /* hotspot: nova variante adicionada */
  ${(props) =>
    props.variant === "danger" &&
    `
    background-color: var(--error-color);
    border-color: var(--error-color);
  `}
`;
```

## 7. Visão Crítica

A implementação dos componentes de UI no projeto AquiTemFCTE demonstra uma compreensão sólida dos princípios de design system e arquitetura de componentes React. A escolha por componentes funcionais com hooks modernos está alinhada com as melhores práticas atuais do ecossistema React.

**Pontos Fortes**:

- **Modularidade**: A separação clara entre componentes atômicos facilita a manutenção e testes
- **Reutilização**: A implementação de props configuráveis permite alta reutilização sem duplicação de código
- **Consistência**: O uso de styled-components com variáveis CSS garante consistência visual
- **Responsividade**: Todos os componentes possuem tratamento adequado para diferentes tamanhos de tela

**Impacto no Projeto**:
A arquitetura de componentes adotada tem impacto positivo significativo na velocidade de desenvolvimento e na qualidade do código. Novos desenvolvedores podem rapidamente entender e contribuir com o projeto, enquanto a manutenção é simplificada pela centralização da lógica de UI.
