# 4.1.4. Pacotes de uso compartilhado entre camadas com o Turborepo

## 1. Introdução

O projeto utiliza **Turborepo** para organizar um monorepo com múltiplas aplicações e pacotes compartilhados, acessados pela pasta raiz `packages/`.  
Dentro dessa pasta, existem pacotes reutilizáveis que podem ser consumidos por qualquer camada — **frontend ou backend** — como se fossem dependências instaladas no `node_modules`.

Neste documento, são descritos dois conjuntos principais de pacotes compartilhados:

- `@aquitemfcte/core`: serviços e utilitários de uso direto pela aplicação (ex.: autenticação e conversão de arquivos).
- `@repo/eslint-config`: configurações de ESLint compartilhadas para padronizar a qualidade de código em todos os projetos.

## 3. Propósito do Componente

O objetivo deste documento é registrar o papel dos **pacotes de uso compartilhado** do monorepo, explicando:

- **O que eles fazem**:
  - Expor serviços de autenticação (`login_user`, `register_user`) e utilitários como `base64Encode` por meio do pacote `@aquitemfcte/core`.
  - Centralizar configurações de ESLint específicas para projetos React/Next.js no pacote `@repo/eslint-config` (`base`, `react-internal`, `next-js`).

- **Como foram estruturados**:
  - Como um **pacote Node/ESM** com ponto de entrada em `src/index.js` (`@aquitemfcte/core`), usando aliases definidos em `jsconfig.json`.
  - Como um **conjunto de configs ESLint flat** exportadas em arquivos JavaScript (`base.js`, `react-internal.js`, `next.js`), agrupadas no pacote `@repo/eslint-config`.

- **Como isso se conecta à arquitetura**:
  - Esses pacotes podem ser importados por qualquer app em `apps/` (por exemplo, `apps/web`), reduzindo duplicação de código e garantindo consistência entre camadas (frontend, backend, libs internas).

## 4. Reutilização do Componente

### 4.1. Pacote `@aquitemfcte/core`

Este pacote concentra serviços (chamadas de API) e utilitários que podem ser reutilizados em qualquer página/camada do monorepo.

#### 4.1.1. `src/services/user.service.js`

Arquivo responsável pelos serviços de autenticação (registro e login).

```js
import axios from "axios";
import {
  MODE,
  API_MAIN_ENDPOINT,
} from "../../../../apps/web/src/utils/constants.js";

const baseURL = MODE.DEV + API_MAIN_ENDPOINT.AUTH;
// MODE.DEV É "http://localhost:8000/" (URL DO BACKEND EM AMBIENTE DE DESENVOLVIMENTO
// API_MAIN_ENDPOINT.AUTH É "auth" (ENDPOINT DE AUTENTICAÇÃO DO BACKEND)

// AQUI TEM A FUNÇÃO DE REGISTRAR USUÁRIO QUE É ACIONADA NA PÁGINA DE CADASTRO
// ESSA FUNÇÃO RECEBE OS DADOS DO USUÁRIO E FAZ UMA REQUISIÇÃO POST PARA O BACKEND
// PARA A ENDPOINT "auth/register", ENVIANDO OS DADOS NO FORMATO JSON
export async function register_user(userData) {
  try {
    const response = await axios.post(`${baseURL}/register`, {
      fullname: userData.name,
      email: userData.email,
      matricula: userData.matricula,
      password: userData.senha,
      confirm_password: userData.confirmarSenha,
      profile_image: userData.profileImage,
    });

    return response.data;
  } catch (error) {
    console.error("Erro ao registrar usuário:", error);
    throw error;
  }
}

// Função para realizar login — envia credenciais como form-urlencoded (compatível com OAuth2PasswordRequestForm)
export async function login_user(email, password) {
  try {
    const params = new URLSearchParams();
    params.append("username", email);
    params.append("password", password);

    const response = await axios.post(`${baseURL}/login`, params, {
      headers: {
        "Content-Type": "application/x-www-form-urlencoded",
      },
    });

    return response.data;
  } catch (error) {
    console.error("Erro ao realizar login:", error);
    throw error;
  }
}
```

**Reutilização:**
- Páginas de **Cadastro**: chamam `register_user(userData)` para registrar o usuário.
- Páginas de **Login**: chamam `login_user(email, password)` para autenticação.
- Qualquer outra camada que precise reutilizar a mesma lógica de autenticação pode importar essas funções do pacote `@aquitemfcte/core`.

#### 4.1.2. `src/utils/base64.js`

Função utilitária para converter arquivos em base64, reaproveitável em qualquer fluxo que envolva upload de arquivos.

```js
export function base64Encode(file) {
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.readAsDataURL(file);
    reader.onload = () => resolve(reader.result);
    reader.onerror = (error) => reject(error);
  });
}
```

**Reutilização:**
- Upload de **imagem de perfil**.
- Qualquer componente que precise transformar um `File` em string base64 antes de enviar ao backend.

#### 4.1.3. `src/index.js`

Ponto de entrada do pacote, reexportando serviços e utils de forma centralizada.

```js
// SERVICES
export { login_user, register_user } from "./services/user.service.js";

// UTILS
export { base64Encode } from "./utils/base64.js";
```

**Reutilização:**
- Permite consumir tudo com uma única importação, por exemplo:

```js
import { register_user, login_user, base64Encode } from "@aquitemfcte/core";
```

#### 4.1.4. `jsconfig.json`

Configuração de paths e `baseUrl` para facilitar imports internos dentro do pacote.

```json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@aquitemfcte/utils/*": ["src/utils/*"],
      "@aquitemfcte/services/*": ["src/services/*"]
    }
  },
  "include": ["src/**/*"]
}
```

**Reutilização:**
Permite imports como:

```js
import { base64Encode } from "@aquitemfcte/utils/base64";
import { login_user } from "@aquitemfcte/services/user.service";
```

### 4.2. Pacote `@repo/eslint-config`

Este pacote concentra as configurações de ESLint compartilhadas por todas as aplicações e libs do monorepo.

#### 4.2.1. `base.js`

Configuração base compartilhada de ESLint.

```js
import js from "@eslint/js";
import eslintConfigPrettier from "eslint-config-prettier";
import turboPlugin from "eslint-plugin-turbo";
import tseslint from "typescript-eslint";
import onlyWarn from "eslint-plugin-only-warn";

/**
 * A shared ESLint configuration for the repository.
 *
 * @type {import("eslint").Linter.Config[]}
 * */
export const config = [
  js.configs.recommended,
  eslintConfigPrettier,
  ...tseslint.configs.recommended,
  {
    plugins: {
      turbo: turboPlugin,
    },
    rules: {
      "turbo/no-undeclared-env-vars": "warn",
    },
  },
  {
    plugins: {
      onlyWarn,
    },
  },
  {
    ignores: ["dist/**"],
  },
];
```

**Reutilização:**
- Serve como base para outras configs (`react-internal`, `next-js`).
- Pode ser usada em qualquer pacote JS/TS do monorepo que não dependa diretamente de React/Next.

#### 4.2.2. `react-internal.js`

Configuração para projetos React que **não** são Next.js (libs internas, por exemplo).

```js
import js from "@eslint/js";
import eslintConfigPrettier from "eslint-config-prettier";
import tseslint from "typescript-eslint";
import pluginReactHooks from "eslint-plugin-react-hooks";
import pluginReact from "eslint-plugin-react";
import globals from "globals";
import { config as baseConfig } from "./base.js";

/**
 * A custom ESLint configuration for libraries that use React.
 *
 * @type {import("eslint").Linter.Config[]} */
export const config = [
  ...baseConfig,
  js.configs.recommended,
  eslintConfigPrettier,
  ...tseslint.configs.recommended,
  pluginReact.configs.flat.recommended,
  {
    languageOptions: {
      ...pluginReact.configs.flat.recommended.languageOptions,
      globals: {
        ...globals.serviceworker,
        ...globals.browser,
      },
    },
  },
  {
    plugins: {
      "react-hooks": pluginReactHooks,
    },
    settings: { react: { version: "detect" } },
    rules: {
      ...pluginReactHooks.configs.recommended.rules,
      // React scope no longer necessary with new JSX transform.
      "react/react-in-jsx-scope": "off",
    },
  },
];
```

**Reutilização:**
- Usada em bibliotecas React internas (component libraries etc).
- Garante boas práticas de React e Hooks sem amarrar ao ambiente Next.js.

#### 4.2.3. `next.js`

Configuração específica para projetos que usam **Next.js**.

```js
import js from "@eslint/js";
import { globalIgnores } from "eslint/config";
import eslintConfigPrettier from "eslint-config-prettier";
import tseslint from "typescript-eslint";
import pluginReactHooks from "eslint-plugin-react-hooks";
import pluginReact from "eslint-plugin-react";
import globals from "globals";
import pluginNext from "@next/eslint-plugin-next";
import { config as baseConfig } from "./base.js";

/**
 * A custom ESLint configuration for libraries that use Next.js.
 *
 * @type {import("eslint").Linter.Config[]}
 * */
export const nextJsConfig = [
  ...baseConfig,
  js.configs.recommended,
  eslintConfigPrettier,
  ...tseslint.configs.recommended,
  globalIgnores([
    // Default ignores of eslint-config-next:
    ".next/**",
    "out/**",
    "build/**",
    "next-env.d.ts",
  ]),
  {
    ...pluginReact.configs.flat.recommended,
    languageOptions: {
      ...pluginReact.configs.flat.recommended.languageOptions,
      globals: {
        ...globals.serviceworker,
      },
    },
  },
  {
    plugins: {
      "@next/next": pluginNext,
    },
    rules: {
      ...pluginNext.configs.recommended.rules,
      ...pluginNext.configs["core-web-vitals"].rules,
    },
  },
  {
    plugins: {
      "react-hooks": pluginReactHooks,
    },
    settings: { react: { version: "detect" } },
    rules: {
      ...pluginReactHooks.configs.recommended.rules,
      // React scope no longer necessary with new JSX transform.
      "react/react-in-jsx-scope": "off",
    },
  },
];
```

**Reutilização:**
- Usada em apps Next.js (por exemplo, o frontend principal).
- Garante regras adequadas para React, Hooks, Next e Core Web Vitals.

## 5. Utilização na Aplicação

### 5.1. `@aquitemfcte/core`

**Fluxo de Cadastro de Usuário (frontend)**

- O formulário de cadastro importa e chama `register_user(userData)` ao submeter.
- O serviço:
  - Monta a URL a partir de `MODE.DEV` e `API_MAIN_ENDPOINT.AUTH`.
  - Mapeia os campos do formulário para o payload esperado pelo backend (`fullname`, `matricula` etc).
  - Retorna `response.data` e propaga erros em caso de falha.

**Fluxo de Login (frontend)**

- O formulário de login importa e chama `login_user(email, password)`.
- O serviço:
  - Usa `URLSearchParams` para montar o corpo `application/x-www-form-urlencoded`.
  - Define o header `"Content-Type": "application/x-www-form-urlencoded"`.
  - Envia a requisição para `${baseURL}/login` e retorna `response.data`.

**Upload e manipulação de imagem de perfil**

- Componentes que recebem um `File` (ex.: input de foto) utilizam `base64Encode(file)` para converter a imagem em string base64 antes de enviar ao backend.
- A mesma função pode ser reaproveitada em qualquer página que trabalhe com upload de arquivos.

### 5.2. `@repo/eslint-config`

**Configuração de ESLint nos apps Next.js (ex.: `apps/web`)**

- A configuração do ESLint pode importar `@repo/eslint-config/next-js` para:
  - Aplicar regras específicas de Next.js.
  - Habilitar checagens de Core Web Vitals.
  - Garantir o uso correto de React e React Hooks.

**Configuração de ESLint em libs React internas**

- Bibliotecas React dentro de `packages/` podem estender `@repo/eslint-config/react-internal` para:
  - Padronizar o uso de Hooks.
  - Usar as mesmas regras de JSX e globals de browser em todo o monorepo.

**Configuração de ESLint em outros pacotes JS/TS**

- Pacotes que não dependem diretamente de React/Next podem usar `@repo/eslint-config/base` como configuração padrão:
  - Compartilham o mesmo estilo de código (JS/TS + Prettier).
  - Herdam regras comuns de qualidade e organização de código.

## 6. Senso Crítico e Trabalho em Equipe

A produção deste artefato exigiu **senso crítico** para decidir o que realmente valia a pena virar pacote compartilhado, além de como documentar de maneira sucinta e com sentido. Foi necessário analisar se a estrutura dos pacotes, pontos de entrada e exemplos de uso ajudavam de fato outras pessoas a reutilizar os serviços e configs dentro do monorepo.

Também foi fundamental o **trabalho em equipe**, com uma divisão clara entre quem focou mais na codificação dos pacotes, e quem organizou e escreveu a documentação. Essa separação de responsabilidades deixou o processo mais eficiente e resultou em uma implementação importante para a reutilização de software, facilitando que todo o time use as mesmas soluções sem retrabalho.

## 7. Conclusão

Os **pacotes compartilhados em `packages/`**, estruturados com Turborepo, cumprem dois papéis centrais na arquitetura:

1. **Centralizar lógica de domínio reutilizável**, como serviços de autenticação e utilitários (`@aquitemfcte/core`), que podem ser consumidos por múltiplas páginas e camadas sem duplicação de código.
2. **Padronizar práticas de desenvolvimento**, via configurações de ESLint compartilhadas (`@repo/eslint-config`), garantindo consistência de estilo, uso de React/Next e integração com o fluxo do monorepo.

Essa abordagem:

- Reduz acoplamento entre aplicações;
- Facilita manutenção e evolução do projeto;
- Cria uma base sólida para acrescentar novos serviços/utilitários compartilhados no futuro (por exemplo, interceptors de `axios`, helpers de tratamento de erro, novas configs de ferramentas etc).
